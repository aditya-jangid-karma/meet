Setting Up the Mac (AI + Files) and Windows PCs (Run the Script)

A step-by-step, plain-English setup guide for Team D (Puneet, Dhruv, Manish, Vijayesh)

Written: 2026-07-30  |  Revised: 2026-08-04 (script now runs on Windows)  |  Level: no coding background required

What we're setting up. The invoice-reading script needs help from an AI model (called Qwen) to correctly identify vendors that only appear as a logo or name at the top of a page — the cases the current script misses (Happy Summers, Quill, Chadwell Supply, etc.). Qwen runs on a Mac, for privacy: client invoice data stays inside the office network and never goes to a cloud AI service.

The important change (revised 2026-08-04). An earlier draft of this guide had the script running on the Mac. That won't work for Team D — everyone uses Windows. So the design is now split cleanly by machine:

  • The Mac does two things only: runs Qwen (the AI), and hosts the shared folder where PDFs and the Excel report live. No Python, no script, nothing to run on it day to day.
  • The Windows PC runs the script — exactly like Team D already did before any of this AI work. When it hits the vendor step, it asks the Mac's Qwen over the office network and carries on.
No API keys anywhere. The local Qwen (via Ollama) needs no account, no key, no login. If any website ever offers you a "Qwen API key," that's the paid cloud version (Alibaba Cloud / DashScope) — do not use it; it would send client data off-site. Our Qwen is the free local one.

1. What we're building, in one picture

WINDOWS PC  (runs the script — 1 to 3 of these)     MAC  (AI + file host only)
-----------------------------------------------      --------------------------
Has installed: Python + Tesseract + the script       Runs: Ollama + Qwen
                                                      (model qwen2.5vl:7b)
Drops PDFs into  Z:\input   ───(shared folder)───►    lives on the Mac at
                                                      ~/Res1/input/
Runs:  python invoice_boundary_detector.py
              │
              │   "Who is the vendor on this page?"
              └──────────(office network)───────────►  Qwen answers
                                                        http://:11434
              │
              ▼
Writes the report back to  Z:\output\reports\predictions.xlsx  (also on the Mac)
Finished PDFs move to      Z:\input\_processed\

Two separate connections run between the PCs and the Mac, and it helps to keep them straight:

  • The shared folder (the Z: drive) — how files get to and from the Mac. This is macOS File Sharing.
  • The Qwen call (to port 11434) — how the script asks the AI who the vendor is. This is Ollama on the network.

They're set up in separate steps below and can be tested separately.

2. Glossary — key terms explained

File share
A folder on one computer that other computers on the same network can open and use as if it were their own — no copying files back and forth by hand. Here, the Mac shares a folder that the Windows PCs use.
SMB
("Server Message Block") — the language computers use to talk to a file share over a network. macOS and Windows both understand it natively, so no extra software is needed.
IP address
A set of numbers (like 192.168.1.42) that identifies one computer on your local network — like a street address, but for a device. The Windows PCs need the Mac's IP address to reach both its shared folder and its Qwen.
Mapped drive
A Windows shortcut that makes a folder on another computer show up as its own drive letter (like Z:), so it behaves just like a local folder.
Ollama
Free software that runs an AI model directly on the Mac, privately, with no internet needed once the model is downloaded. This is what keeps client invoice data from leaving the office.
Qwen
The specific AI model this project uses, running inside Ollama on the Mac. The exact installed version is qwen2.5vl:7b — a "vision" model that can read both text and page images.
Port
A numbered "door" a program listens on for requests. Ollama listens on port 11434 — you'll see that number throughout this guide.
Localhost vs. network address
localhost means "this same computer." By default Ollama only answers localhost, so only the Mac itself can reach it. To let the Windows PCs reach it, we tell Ollama to also answer on the Mac's network address — that's the one-time OLLAMA_HOST step in Part B.
Tesseract
A free tool that reads text out of a picture of a page (OCR). Only needed as a fallback for the rare scanned/photographed invoice. It installs on Windows now (where the script runs), not the Mac.
Path
The exact address of a file or folder, e.g. Z:\input on Windows (backslashes, drive letter) versus /Users/admin/Res1/input on the Mac (forward slashes). This is why config.json uses Windows-style paths now.

3. ON THE MAC Part A — Host the shared folder

This makes the Mac's Res1 folder visible to the Windows PCs as a network drive. It's the same File Sharing feature built into every Mac.

1Create the project folder and subfolders

In Finder, create a folder Res1 in your Home folder, and inside it create:

  • input — where PDFs land
  • input/_processed — where finished PDFs get moved after a successful run (can also be auto-created by the script)
  • output/reports — where predictions.xlsx lives
2Turn on File Sharing and add the folder

Apple menu → System Settings → General → Sharing. Switch File Sharing on. Click the (i) next to it, then + under "Shared Folders" and add Res1.

What you should see: Res1 listed under Shared Folders.

3Give the account Read & Write

Under "Users," make sure the Mac account the Windows PCs will connect with has Read & Write (not "Read Only") — otherwise the script can't save the Excel file or move processed PDFs.

4Note the Mac's name and IP address

In the Sharing pane you'll see an address like smb://Admins-Mac-mini.local — note the name. Then System Settings → Wi-Fi (or Network) → Details → note the IP address, e.g. 192.168.1.42. Write both down — you'll use them from Windows for both the drive and the Qwen address.

Why a fixed IP address matters: the office router can hand the Mac a different IP after a reboot, which would silently break both the Z: drive and the Qwen connection on every Windows PC at once. Ask whoever manages the router to set a DHCP reservation (static lease) for the Mac. If that's not possible yet, using the Mac's name (Admins-Mac-mini.local) instead of the number avoids the problem, as long as the name doesn't change.

4. ON THE MAC Part B — Expose Qwen on the network

This part assumes Ollama and qwen2.5vl:7b are already installed (confirmed working on 2026-08-04). By default Qwen only answers the Mac itself; this one-time change lets the Windows PCs reach it too.

1Confirm Qwen works locally first

Open Terminal (Cmd+Space, type "Terminal") and run:

ollama list

What you should see: a row qwen2.5vl:7b. (Already confirmed for this Mac.) Then prove it answers:

curl http://localhost:11434/api/generate -d '{"model":"qwen2.5vl:7b","prompt":"Say hello in one word.","stream":false}'

What you should see: a JSON reply with a "response" field containing a word like "Hello". No key is asked for — that's expected and correct.

2Tell Ollama to listen on the network

In Terminal, run this one line (it sets Ollama to answer on all network addresses, not just localhost):

launchctl setenv OLLAMA_HOST "0.0.0.0:11434"

Then quit and reopen the Ollama app so it picks up the change: click the Ollama icon in the menu bar at the top of the screen → Quit, then open Ollama again from Applications.

3Confirm it's reachable by address

Still on the Mac, test using the Mac's own IP address (from Part A step 4) instead of localhost:

curl http://192.168.1.42:11434/api/tags

What you should see: the same JSON model list as before. If this works with the IP address, a Windows PC on the same network will be able to reach it too.

Security note (worth knowing): exposing Ollama on the network means any device on the office network can reach port 11434 on the Mac. That's acceptable here — it's a private office network, and Ollama stores no client data (it only answers questions and forgets them). Just don't do this on public Wi-Fi, and never forward this port to the internet.

5. ON EACH WINDOWS PC Part C — Map the shared folder as Z:

1Open Map Network Drive

File Explorer → This PC → right-click → Map network drive…

2Fill it in
  • Drive: Z:
  • Folder: \\Admins-Mac-mini.local\Res1 (or \\192.168.1.42\Res1)
  • Tick Reconnect at sign-in and Connect using different credentials

When prompted, enter the Mac account's username and password (the one you gave Read & Write in Mac Part A step 3).

Test it: create a small text file in Z:\input, then check it appears in Res1/input on the Mac. Delete the test file after.

6. ON EACH WINDOWS PC Part D — Install Python, Tesseract & the script

This is the same software Team D used before the Mac was involved — it just now also knows how to call Qwen.

1Python 3

Install from python.org (tick "Add Python to PATH" during install). Confirm in PowerShell:

python --version
2The script's Python packages

Put the project files (invoice_boundary_detector.py, config.json, requirements.txt) in a local folder, e.g. C:\Users\<you>\Res1, then:

cd C:\Users\\Res1
pip install -r requirements.txt

What you should see: "Successfully installed…" with no red errors.

3Tesseract (OCR fallback for scanned pages)

Install the Windows build of Tesseract (the UB-Mannheim installer is the common one). Note where it lands — usually C:\Program Files\Tesseract-OCR\tesseract.exe. Write that path down for config.json.

Why the script folder is separate from the Z: drive: the script lives locally on each Windows PC (C:\…\Res1), but the PDFs and Excel live on the shared Z: drive. Part E's config.json is what connects the two — it tells the local script to read/write files over on Z:.

7. ON EACH WINDOWS PC Part E — Update config.json

Open config.json (in the local C:\…\Res1 folder) in Notepad. Three things point it at the right places: the Tesseract path, the shared-folder paths, and the Mac's Qwen address.

Example config.json (Windows)
{
  "tesseract_cmd": "C:\\Program Files\\Tesseract-OCR\\tesseract.exe",
  "paths": {
    "input_folder": "Z:\\input",
    "output_folder": "Z:\\output\\reports",
    "processed_folder": "Z:\\input\\_processed"
  },
  "llm": {
    "enabled": true,
    "host": "http://192.168.1.42:11434",
    "text_model": "qwen2.5vl:7b",
    "vision_model": "qwen2.5vl:7b",
    "min_text_chars": 50,
    "image_dpi": 150,
    "timeout_seconds": 120,
    "escalate_to_vision": true
  }
}
Fill in your real values: use the Mac's actual IP (or http://Admins-Mac-mini.local:11434) for host, and your real Tesseract path. The model name must be exactly qwen2.5vl:7b — the ":7b" matters (leaving it off is what caused the "model not found" error during testing). Note the double backslashes \\ in Windows paths — that's required in this kind of file.
When you add a second or third PC, the fastest path is to copy this exact config.json across — every value is identical between PCs, since they all point at the same Z: drive and the same Mac address. The only thing that could differ is the Tesseract path, if a PC installed it somewhere else.

8. ON EACH WINDOWS PC Part F — First test run

1Offline self-test first
cd C:\Users\\Res1
python invoice_boundary_detector.py --selftest

Healthy result: every check reports PASS. This needs no network and doesn't touch Qwen — it just proves the install itself is sound.

2Confirm the PC can reach Qwen on the Mac

In PowerShell:

curl http://192.168.1.42:11434/api/tags

Healthy result: a JSON list showing qwen2.5vl:7b. If this fails but the Mac's own test in Part B worked, see the FAQ ("Windows can't reach Qwen").

3A real small run

Drop 2–3 PDFs into Z:\input, then:

python invoice_boundary_detector.py

Healthy result: progress prints per PDF, no Python "Traceback" error, and Z:\output\reports\predictions.xlsx updates. (The vendor logic that uses Qwen is the code work in Deliverable B — if that isn't finished yet, this run still proves the plumbing: files, network, and Qwen are all wired correctly.)

9. Adding another Windows PC later (quick checklist)

Nothing on the Mac changes when you add a PC — the Mac work (Parts A & B) is done once, for good. Adding PC #2 or #3 is just repeating the Windows parts:

  • Map the Mac's shared folder as Z: (Part C)
  • Install Python 3 and pip install -r requirements.txt (Part D, steps 1–2)
  • Install Windows Tesseract (Part D, step 3)
  • Copy the same config.json onto this PC (Part E) — adjust the Tesseract path only if needed
  • Run --selftest, then the Qwen reachability check, then a small real run (Part F)
One shared report, many PCs. Because every PC reads and writes the same predictions.xlsx on Z:, avoid two people running the script at the exact same moment, and make sure nobody has the Excel file open in Excel while a run is writing to it (that causes a "permission denied" — see the FAQ).

10. Troubleshooting FAQ

Windows can't reach Qwen ("connection refused" or timeout on port 11434).

Almost always the OLLAMA_HOST step (Mac Part B step 2) hasn't taken effect. On the Mac, confirm the network test there works (curl http://<mac-ip>:11434/api/tags using the IP, not localhost). If the Mac test works with the IP but Windows still can't reach it, check the Mac's Firewall (System Settings → Network → Firewall) isn't blocking incoming connections — either turn it off on a trusted office network, or allow Ollama through it. Also double-check both machines are on the same network.

"model 'qwen2.5vl' not found."

The model name is missing its tag. It must be written exactly qwen2.5vl:7b — with the :7b — everywhere: in the curl test and in config.json's text_model / vision_model. Run ollama list on the Mac to see the exact name in the NAME column.

Windows can't see the Mac's Z: drive at all.

Confirm both computers are on the same network. On the Mac, re-check System Settings → General → Sharing → File Sharing is on. Try connecting with the Mac's IP address instead of its name (or vice versa) — sometimes one resolves when the other doesn't.

The Z: drive or Qwen worked yesterday but is gone after a Mac restart.

The Mac's IP address likely changed on reboot. This breaks both the drive and the Qwen address at once. Fix it properly with a DHCP reservation for the Mac (Mac Part A note), or use the Mac's name (Admins-Mac-mini.local) instead of the number in both the mapped drive and config.json's host.

"Permission denied" writing predictions.xlsx.

Two common causes: (1) the Excel file is open in Excel on someone's PC — close it before running; (2) the Mac account's File Sharing permission on Res1 reverted to Read Only — re-check Mac Part A step 3.

The Mac went to sleep and runs started failing.

A Mac acting as the office's AI + file host should stay awake and plugged in. System Settings → Lock Screen / Battery → prevent automatic sleeping while on power. If Ollama seems "asleep," reopening the Ollama app wakes it.

Do I need an API key for Qwen?

No — the local Qwen (via Ollama) has no keys at all. The fact that the test command answered without one is the proof. Anything asking you to "generate a Qwen API key" is the paid cloud service (Alibaba Cloud / DashScope), which would send client data off-site — don't use it.
